Prefixer is an agent skill for scoped codebase search.

AI coding agents that grep the whole tree pay for every irrelevant hit in tokens and tool calls. Prefixer gives the agent a small namespace map — a table of short prefixes to the parts of the repo that matter — so searches start scoped, widen only on a miss, and land inside the right files first.

It is plain Markdown and shell scripts, not a service and not an MCP server. One SKILL.md, five reference playbooks, and a small script toolkit — scaffold, lint, measure, eval, test. It works with any agent that reads skills: Devin, Claude Code, Codex, Cursor, and friends.

How it works

  • Scope first. On entry to a repo, the agent reads .prefixer/namespaces.md — rows like auth: | src/auth/** | login, tokens, sessions — and searches inside the matching namespace instead of the tree.
  • Derived, not declared. The scaffold names namespaces from the codebase's own vocabulary — distinguishing dir-name segments, dominant file terms — never a hardcoded wordlist. Every map carries a repo: qualifier, so payments:auth: and checkout-service:auth: stay distinct across codebases, and rows nest for sub-teams (payments:checkout:).
  • Map the segment, not the world. No map? The agent builds only the 3–5 namespaces the current task touches. A partial map is a legal, working state.
  • Widen one level on a miss. A scoped search that misses widens to the parent scope, then the root — never a blind second pass.
  • Measure the delta. Each scoped search appends a line to .prefixer/metrics.jsonl; check_namespaces.sh lints the map for dead scopes and eval_repo.sh proves the bytes saved.

Install

npx skills add Albisourous/prefixer

Or copy SKILL.md, references/, and scripts/ into .agents/skills/prefixer/ (or .devin/skills/prefixer/, ~/.config/devin/skills/ for Devin) in your project. Full instructions in the README.

Good fit if

  • You work in a large repo, a monorepo, or many codebases at once.
  • Agent searches return walls of hits from the wrong modules.
  • You want a persistent orientation map future sessions reuse.
  • You index docs or chunks for RAG and want tighter embeddings.
  • You care about prompt-cache hits and token cost, measured not guessed.

Three prefix positions

Where the prefix goesWhat it buys
In front of a search (auth:, src/api/) Fewer tool calls, smaller results — fewer tokens exploring
In front of a doc at index time Tighter embedding clusters — better Hit@k, zero fine-tuning
At the front of a prompt Prompt-cache hits — cheaper input, faster TTFT

The index-time and cache-ordering playbooks ship in references/. The research base — Anthropic Contextual Retrieval, index-time prefix injection (ACL 2026), Prompt Cache, RadixAttention — is collected in DESIGN.md.
